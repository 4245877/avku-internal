## 3. Docker и развёртывание

Редеплой требовался для замены точечных image patches обычной сборкой и для
актуализации recovery sources. Применяется единая композиция:

```
docker-compose.prod.yml + docker-compose.backup.yml + docker-compose.release.yml
```

| Worker | `avku-internal-backup-worker:audit-20261027` | `bb1cdb88a725` |

Release tags совпадают с финальными работающими контейнерами. Nginx остался на
прежнем digest `65645c7bb6a0`; конфигурация проверена и upstream DNS перечитан
reload. Cloudflare connector и 12 прочих контейнеров не пересоздавались.

218 API/recovery-Web/public/template файлов работающего image побайтово совпали
с checkout; отсутствующих исходных файлов нет. Полная ordinary Compose-сборка
успешна. Повторный build меняет Compose labels/provenance metadata; файловые слои
и runtime config worker совпали с проверенным экспортом. Финальные контейнеры
закреплены на результатах стандартной Compose-сборки. Сборки API и Web прямо из
восстановленного backup recovery-context также успешны, без исходного checkout.
Apt mirror остаётся внешним источником Debian packages: это функциональная
воспроизводимость, а не обещание побитово одинакового image tar в будущем.

`/var/lib/avku-internal/data:/data` сохранён. Worker не имеет `/data`/Docker socket,
работает uid 1000, read-only rootfs, dropped capabilities; SSH mounts RO.
API server работает как `node` после entrypoint; web — uid 101 nginx. Env и
постоянные mounts сохранены. Никакие данные не зависят от writable container layer.

Перед cutover созданы online/full backups, проверено отдельное восстановление,
